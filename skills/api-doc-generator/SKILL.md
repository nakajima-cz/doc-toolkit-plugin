# API設計書生成スキル

既存のバックエンドソースコードを解析し、API設計書を生成する。

## 事前準備

作業開始前に、以下の設定ファイルを読み込んでください:

- `.claude/project-config.md` — バックエンド構造、IaC定義ファイル位置、ルーティング定義ファイル位置

このスキルはプロジェクト構造に応じて、IaC定義ファイル（`.claude/project-config.md` 参照）または
ルーティング定義ファイルを解析してAPI仕様を抽出します。

## 解析ワークフロー

### Step 1: ルーティング定義の収集

まず IaC定義ファイル（`.claude/project-config.md` の「バックエンド構成」に指定）を読み、ルーティング定義を抽出する。

抽出対象:
- HTTPメソッド（GET/POST/PUT/DELETE/PATCH）
- パスパターン（`/api/v1/users/{id}` 等）
- 対応するバックエンド関数名
- 認証設定

IaC定義ファイルが存在しない場合や情報が不十分な場合は、
バックエンド関数ディレクトリ配下のハンドラファイルを直接走査する。

外部連携サービス側については、`.claude/project-config.md` に指定された
ルーティング定義ファイルを解析する。

### Step 2: 各エンドポイントの詳細解析

各バックエンド関数のハンドラファイルを読み、以下を抽出する:

1. **リクエスト仕様**
   - パスパラメータ・クエリパラメータ
   - リクエストボディのJSON構造
   - 必須/任意の区別（バリデーション処理から推定）

2. **レスポンス仕様**
   - ステータスコード
   - レスポンスボディのJSON構造
   - エラーレスポンスのパターン

3. **認証・認可**
   - JWT検証の有無（認証検証関数、`.claude/project-config.md` 参照）
   - 対象ロール

4. **関連処理**
   - DB操作（テーブル名、CRUD種別）
   - メッセージキュー送信
   - 外部API呼び出し

### Step 3: ドキュメント生成

収集した情報を以下のテンプレートに従って出力する。
出力形式はユーザーの指示に応じてMarkdown（デフォルト）またはdocxとする。


## 出力テンプレート

`references/api-doc-template.md` を参照して出力フォーマットに従う。

## 解析のコツ

- ハンドラのシグネチャを特定し、イベント引数からパラメータを取得するパターンを追う
- レスポンスフォーマットは実装言語に応じて異なるため、返却値の構造を追跡する
- 共通処理は共通ライブラリに記載されているため、参照が見つかったら追跡する
- バリデーションロジックから必須パラメータを推定できる
- エラーハンドリングパターンからエラーレスポンスを網羅する

## スコープ指定

ユーザーが「全API」と指示した場合は全バックエンド関数を対象とする。
特定の機能を指示された場合は、該当するディレクトリに絞って解析する。

解析対象が多い場合（10エンドポイント超）は、まずエンドポイント一覧を提示し、ユーザーに確認を取ってから詳細解析に進む。

## 注意事項

- ソースコードから推定できない情報（ビジネス上の制約、非機能要件等）は「要確認」と明記する
- 既存のAPI設計書がある場合は差分更新モードで動作し、変更点のみをハイライトする
- レスポンスのサンプルデータは実際のコードから推定可能な範囲で生成し、推測部分は明示する
