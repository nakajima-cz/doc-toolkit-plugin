# バックエンド実装 品質チェックリスト

> 実装完了後、コードを書き終えた直後に確認する。
> すべての項目が OK になってから設計書更新フローに進む。

---

## 1. コーディング規約チェック

- [ ] 各ファイルの先頭またはメソッド直前に実装意図のコメントを記載した
- [ ] `TODO:` / `NOTE:` / `FIXME:` / `HACK:` コメントを必要な箇所に付けた
- [ ] 変数名・メソッド名が省略なく、意図が伝わる命名になっている
- [ ] マジックナンバーを定数に切り出し、コメントで意味を説明した
- [ ] ネストが 3 段以上になっている箇所をメソッド抽出で平坦化した
- [ ] 複雑な条件式をローカル変数または述語メソッドに切り出した

---

## 2. プロジェクト規約チェック

- [ ] ハンドラのシグネチャが `.claude/project-config.md` の定義と一致している
- [ ] 認証が必要なエンドポイントに認証検証関数を適用している
- [ ] 共通ライブラリは `.claude/project-config.md` に記載のパスから require / import している
- [ ] エラーレスポンスのフォーマットが既存のAPIと統一されている
- [ ] 環境変数を追加した場合、IaC 定義ファイル（template.yaml 等）にも追記した

---

## 3. 安全性チェック

- [ ] SQL インジェクション対策（プレースホルダ or ORM のクエリビルダを使用）
- [ ] 入力値のバリデーションが実装されている
- [ ] 外部からの入力を直接 eval / exec / system に渡していない
- [ ] 認証トークン・シークレットをログに出力していない
- [ ] トランザクション処理が必要な DB 操作にトランザクションを適用した

---

## 4. 実装の完全性チェック

- [ ] 実装計画で挙げたすべてのファイルを変更した
- [ ] エラーケース（バリデーション失敗、DB エラー、外部 API エラー等）を処理した
- [ ] 正常系・異常系ともにレスポンスを返している
- [ ] 既存のコードに意図しない影響を与えていない（変更の影響範囲を確認）

---

## 5. doc-first モード専用チェック

- [ ] 設計書に記載されたすべての仕様がコードに反映されている
- [ ] 設計書の Input/Output 仕様とコードの振る舞いが一致している
- [ ] コードにあるが設計書に記載のない処理をユーザーに報告した
