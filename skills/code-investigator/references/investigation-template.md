# 調査レポートテンプレート

ドキュメント冒頭に以下の注記を必ず記載する:

```
> **調査日**: YYYY-MM-DD
> **クエリ**: 「ユーザーの元の質問をそのまま記載」
> **ファイルパス・行番号は調査日時点のソースコードに基づきます**
```

---

## 目次の要否

| レポート規模 | 目次 | 理由 |
|------------|------|------|
| 小規模（5節以下） | 省略可 | スクロール量が少なくナビゲーション不要 |
| 中〜大規模（6節以上 or 複数コンポーネント横断） | **必須** | 節間ジャンプで可読性が大幅向上 |

大規模レポートの目次テンプレート:

```markdown
## 目次

1. [全体アーキテクチャ](#1-全体アーキテクチャ)
2. [ComponentA](#2-componenta)
3. [ComponentB](#3-componentb)
   ...
N. [要確認事項・既知の問題](#N-要確認事項既知の問題)
N+1. [関連ファイル一覧](#N1-関連ファイル一覧)
```

アンカーリンクの変換ルール: 日本語・英語ともに小文字化し、スペースと記号を `-` に置換。
例: `## 2. SyncAgentFunction — 委託先同期 + エンキュー` → `#2-syncagentfunction--委託先同期--エンキュー`

---

## セクション選択ガイドライン

質問の性質に応じてパターンを選択する。複数パターンの組み合わせも可。

| 質問の性質 | 推奨パターン |
|-----------|------------|
| 「〇〇の流れを教えて」 | A (処理フロー型) |
| 「〇〇のステータスは？」 | B (状態遷移型) |
| 「〇〇テーブルの構造は？」 | C (データ構造型) |
| 「SQSで何が流れてる？」 | D (アーキテクチャ型) |
| 「AとBの違いは？」 | E (比較型) |
| 「〇〇を調べて」（漠然） | F (機能概要型) |
| 「購入→配送→完了の全体像」 | A + D の組み合わせ |
| 「チケット管理のデータと状態」 | B + C の組み合わせ |

## 記述ルール

1. 全セクションでコード参照（ファイルパス#行番号）を併記する
2. サマリーは必ず質問への直接回答を含める。詳細はその後のセクションに委ねる
3. 関連コンポーネントは調査で発見した全要素を漏れなく記載する
4. 詳細セクションの構成は質問に合わせて柔軟に決定する。テンプレートの機械的適用はしない
5. 推測情報は「要確認」に回す。本文に推測を紛れ込ませない
6. 既存ドキュメントを参照した場合は「参照した既存ドキュメント」に必ず記載する
