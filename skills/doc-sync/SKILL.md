# ドキュメント同期スキル (doc-sync)

ソースコードリポジトリの変更を git 履歴から検出し、ドキュメントの古くなったファイルを自動更新する。

## 事前準備

作業開始前に、必ず以下のファイルを読み込んでください:

1. `.claude/project-config.md` — プロジェクト固有の技術スタック・ディレクトリ構造
2. `.claude/skills/doc-sync/references/path-mapping.md` — ソース → ドキュメントのパスマッピング

`project-config.md` の「doc-sync 設定」セクションからパスマッピング・除外パターンの概要を把握し、
`path-mapping.md` で詳細な対応関係を確認してください。

> **注意**: `path-mapping.md` と `check-stale-docs.sh` はプロジェクト固有の設定です。
> 新しいプロジェクトに適用する際は、これらを書き換えてください。

## 実行フロー

### Step 1: パスマッピングを確認する

`.claude/skills/doc-sync/references/path-mapping.md` を Read して
ソースファイル → ドキュメントファイル → 使用エージェントのマッピングルールを把握する。

### Step 2: 変更検出スクリプトを実行する

以下のコマンドで陳腐化・未生成のドキュメントを検出する:

```bash
bash .claude/skills/doc-sync/check-stale-docs.sh
```

スクリプトの出力フォーマット:
- `STALE <type> <src_path> -> <doc_path> (src: <date>, doc: <date>)` — ドキュメントが古い
- `MISSING <type> <src_path> -> <doc_path>` — ドキュメントが未生成

### Step 3: 結果を整理してユーザーに報告する

スクリプトの出力をもとに、以下の形式で検出結果をサマリー表示する:

```
## ドキュメント同期チェック結果

### 更新が必要なドキュメント
| カテゴリ | ソース | ドキュメント | ソース最終更新 |
|---|---|---|---|
| backend | {src_path} | {doc_path} | {date} |
...

### 未生成のドキュメント
| カテゴリ | ソース | 作成先 |
|---|---|---|
...

合計: XX件（更新: XX件 / 新規: XX件）
```

件数が 0 件の場合は「すべてのドキュメントが最新です」と報告して終了する。

### Step 3.5:【確認②】更新内容の差分提示とユーザー承認

ドキュメントの更新を開始する前に、各ドキュメントで何が変わるかをユーザーに提示し、承認を得る。

```
## 更新予定のドキュメント差分

以下のドキュメントを更新します。確認してください。

### backend/api/cart/POST_cart.md
- リクエストボディに `coupon_code` フィールドを追加（文字列・任意）
- レスポンス例を最新の実装に合わせて更新

### frontend/screens/cart/cart.md
- カートページの表示項目にクーポン入力欄を追加
- ...

上記の更新を適用してよいですか？
```

**ユーザーが承認するまで、doc生成スキルの起動を行わない。**
ユーザーが一部のドキュメントのみ更新を指示した場合は、その指示に従って対象を絞る。

### Step 4: ドキュメントを自動更新する

検出された各アイテムに対して、Taskツールで `path-mapping.md` に記載された対応エージェントをspawnする。

**並列実行のルール**:
- 同カテゴリ内の更新は並列実行可能
- エージェントが同じファイルを同時編集しないよう、同一ファイルへの更新は直列化
- 一度に起動するエージェントは最大 5 件とし、完了を確認してから次の 5 件を実行

エージェントへのpromptテンプレート:
```
ドキュメント同期作業です。

【対象】
- ソース: {src_path}
- ドキュメント: {doc_path}

【作業内容】
{src_path} が {src_date} に更新されています。
{doc_path} 配下の既存ドキュメントを、最新のソースコードに基づいて更新してください。

ドキュメントが存在しない場合は新規作成してください。
ドキュメントが存在する場合は既存ファイルを上書き更新してください。

【注意】
- 対応するスキルのSKILL.mdの手順に従う
- 全セクションにファイルパス・行番号を併記すること
```

### Step 5: 全エージェントの完了を待って最終報告する

全エージェントの完了後、以下を報告する:

```
## ドキュメント同期 完了

更新完了: XX件
- {doc_path} ✓
...

スキップ（変更なし）: XX件
エラー: XX件（あれば詳細）
```

## 即時同期モード（backend-implement / frontend-implement から呼ばれる場合）

`backend-implement` または `frontend-implement` スキルからコード変更後に呼ばれる場合は、
**即時同期モード**で動作する。git 履歴を参照する代わりに、受け取ったファイルリストを使用する。

### 即時同期モードの判定

呼び出し側のプロンプトに「即時同期モードで実行してください」または「--immediate」が含まれている場合、
このモードで動作する。

### 即時同期モードのフロー

#### Step I-1: 変更ファイルリストを受け取る

呼び出し側（backend-implement / frontend-implement / feature-implement）から
渡された変更ファイルリストを使用する。check-stale-docs.sh は実行しない。

#### Step I-2: パスマッピングで影響ドキュメントを解決する

`path-mapping.md` を参照し、変更ファイルに対応するドキュメントを特定する。

| 変更ファイルのパターン | 対応する設計書 | 使用するエージェント |
|---|---|---|
| backend/function/{category}/ | backend/api/{category}/ | backend-detail-doc |
| {app}/pages/{screen}/ | {app}/screens/{screen}/ | frontend-spec-doc |
| db_scheme.sql / マイグレーション | backend/er/ | er-diagram-gen |
| モデルファイル | backend/docs/models/ | db-model-doc |

ページ・コンポーネントの変更が含まれる場合は `screen-transition-gen` も更新対象に追加する。

#### Step I-3: 影響ドキュメントの一覧と差分予測を提示する

**通常モードの Step 3.5 と同様に、ユーザーに確認を求める。**

```
## ドキュメント更新予定（即時同期）

以下のドキュメントを更新します。確認してください。

| ドキュメント | 更新理由 | 想定される変更内容 |
|---|---|---|
| {doc_path} | {src_path} が変更されたため | {変更内容の概要} |

上記の更新を適用してよいですか？
```

#### Step I-4: 承認後にdoc生成スキルを起動する

通常モードの Step 4 と同じルールで対応エージェントを起動する。

## カスタマイズ方法

新しいプロジェクトで doc-sync を使用する場合、以下のファイルを編集してください:

1. **`references/path-mapping.md`** — ソース → ドキュメントの対応表を記述
2. **`check-stale-docs.sh`** — シェルスクリプト内のパスマッピング（`BACKEND_MAP` 等）と `SRC_DIR` / `DOC_DIR` を更新

## 注意事項

- スクリプトは `MISSING` と `STALE` 両方を検出するが、いずれも同じエージェントで対応可能
- 大量の更新が検出された場合（20件超）は、バックエンドを優先し、フロントエンドを後から処理する
- エージェントが「変更なし」と判断した場合（スタイル変更のみ等）はスキップして問題ない
- 同期完了後は自動でコミットしない（ユーザーがレビュー後に対応）
