# フロントエンド実装 品質チェックリスト

> 実装完了後、コードを書き終えた直後に確認する。
> すべての項目が OK になってから設計書更新フローに進む。

---

## 1. コーディング規約チェック

- [ ] 各コンポーネントの先頭またはロジックの直前に実装意図のコメントを記載した
- [ ] `TODO:` / `NOTE:` / `FIXME:` / `HACK:` コメントを必要な箇所に付けた
- [ ] 変数名・関数名・コンポーネント名が省略なく、意図が伝わる命名になっている
- [ ] マジックナンバーを定数に切り出し、コメントで意味を説明した
- [ ] 複雑なロジックをカスタムフックに切り出し、コンポーネントを薄く保った
- [ ] `any` 型を使用していない（型定義を明示した）

---

## 2. プロジェクト規約チェック

- [ ] ルーティング方式が `.claude/project-config.md` のフレームワーク設定と一致している
- [ ] APIクライアントは `.claude/project-config.md` に記載の場所（api/ or services/ 等）に配置した
- [ ] 認証が必要なページ・コンポーネントに認証ガードを適用した
- [ ] 状態管理の方式（Context / Zustand / Pinia 等）が既存と統一されている
- [ ] 画面遷移のパターン（`router.push` 等）がプロジェクトの既存パターンと統一されている

---

## 3. 安全性チェック

- [ ] ユーザー入力をそのまま `dangerouslySetInnerHTML` / `v-html` に渡していない（XSS対策）
- [ ] APIリクエストにエラーハンドリングを実装した
- [ ] ローディング状態・エラー状態を UI で適切にハンドリングした
- [ ] 認証トークン・シークレットをコードにハードコードしていない

---

## 4. 実装の完全性チェック

- [ ] 実装計画で挙げたすべてのファイルを変更した
- [ ] フォームにはクライアント側バリデーションを実装した
- [ ] 非同期処理（API呼び出し等）のローディング・エラー状態を処理した
- [ ] 画面遷移が設計書通りに実装されている

---

## 5. doc-first モード専用チェック

- [ ] 設計書に記載されたすべての表示項目・インタラクションがコードに反映されている
- [ ] API連携仕様（エンドポイント・パラメータ・レスポンスの使い方）が設計書と一致している
- [ ] コードにあるが設計書に記載のない実装をユーザーに報告した
