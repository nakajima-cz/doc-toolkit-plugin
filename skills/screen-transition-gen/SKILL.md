# 画面遷移図生成スキル

## 事前準備

作業開始前に、以下の設定ファイルを読み込んでください:

- `.claude/project-config.md` — フロントエンドアプリケーション構造、遷移パターン、ルーティング定義位置

フロントエンドのソースコードを解析し、画面遷移図をMermaid形式で生成します。

## 対象プロジェクト構造

`.claude/project-config.md` の「フロントエンドアプリケーション」セクションを参照してください。
一般的には複数のフロントエンドアプリケーション（ユーザー向け、管理者向け、パートナー向けなど）が存在します。

各アプリは以下の共通構造を持つ:
```
frontend-app-*/
├── pages/            # ページコンポーネント（ルーティング定義）
├── components/       # UIコンポーネント
├── api/              # APIクライアント
├── store/            # 状態管理
├── types/            # 型定義
└── constants/        # 定数
```

## 解析ワークフロー

### Step 1: ページ一覧の収集

ルーティング定義ファイル（`.claude/project-config.md` で指定）を再帰的に走査し、全ルートを収集する。

抽出ルール:
- ルーティング定義の形式に応じて解析（Next.js Pages Router、ファイルベースルーティング等）
- 動的ルートパラメータを `:id` 等のプレースホルダで識別
- 特殊ファイル・API定義は除外

各ページファイルから以下を読み取る:
- ページコンポーネント名
- ページタイトル（メタデータから）
- 認証要否（認証ガード等のラッパーの有無）

### Step 2: 遷移の抽出

各ページおよびコンポーネントから画面遷移を抽出する。

検出パターン:

1. **遷移パターン** （`.claude/project-config.md` 参照）
   - ルーターによる遷移（プログラマティック遷移）
   - リンク要素による遷移
   - パラメータ付き遷移

2. **条件付き遷移**
   - 認証状態による遷移（ログイン → マイページ、未認証 → ログイン画面）
   - フォーム送信後の遷移
   - エラー時の遷移

3. **リダイレクト**
   - サーバーサイドリダイレクト（`.claude/project-config.md` 参照）
   - ミドルウェアによるリダイレクト
   - クライアント側のリダイレクト

各遷移について以下を記録する:
- 遷移元ページ
- 遷移先ページ
- トリガー（ボタンクリック、フォーム送信、リダイレクト等）
- 条件（認証状態、パラメータ等）

### Step 3: Mermaid図の生成

収集した情報をMermaid stateDiagram-v2形式で出力する。

出力フォーマットの詳細は `references/mermaid-format.md` を参照。

## スコープ指定

ユーザーの指示に応じてスコープを調整する:

- **アプリ指定**: 「アプリAの画面遷移図」→ 指定アプリのみ
- **機能指定**: 「購入フロー」→ 購入関連ページに絞る
- **全体**: 「全画面遷移図」→ 全アプリを対象（アプリ別に分割して出力）
- **指定なし**: どのアプリか確認する。1アプリ内でもページ数が多い場合（20ページ超）は機能カテゴリ別に分割を提案する

## 出力の調整

ページ数が多い場合、1枚の図に詰め込むと可読性が下がる。以下の基準で分割する:

- 15ページ以下: 1枚の図で出力
- 16-30ページ: 機能カテゴリ別に2-3枚に分割
- 31ページ以上: 全体概要図（カテゴリ間の遷移のみ）+ カテゴリ別詳細図

## 注意事項

- 動的ルートは `:id` 等のプレースホルダで表現する
- 外部サイトへの遷移（window.location等）は遷移先を「外部: [URL or サービス名]」と表記する
- モーダルやドロワーは画面遷移とは区別し、注釈として記載する
- コンポーネント内で複数の遷移先が条件分岐する場合は、条件をエッジラベルに記載する
- ソースから読み取れない遷移（ユーザー操作の推測等）は含めない。確実にコードに存在する遷移のみ記載する
